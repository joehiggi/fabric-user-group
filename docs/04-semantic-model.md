# 04 · Semantic Model (Direct Lake, TMDL)

## Core concepts
- The **semantic model** is the business layer: tables, relationships, measures (DAX), formats and security.
- **Storage modes:**
  - **Import** copies data into memory. Fast, but needs a scheduled refresh.
  - **DirectQuery** sends queries to the source. Always live, slower.
  - **Direct Lake** reads Delta/Parquet straight from OneLake. Import-like speed with no data copy. A "refresh" only *reframes* to the latest Delta version, which takes seconds.
- **TMDL** (Tabular Model Definition Language) is the model as readable text files, one per table, which makes Git diffs easy.

## In this repo
`src/powerbi/Sales.SemanticModel/definition/` is generated by `src/tools/build_pbip.py` from one spec.
- **Star schema:** `fact_sales` and `fact_sales_target` → `dim_date`, `dim_customer`, `dim_product`, `dim_sales_rep`, `dim_territory`
- **Ops tables:** `etl_run_log` and `dq_results` (no relationships; feed the Pipeline Health page)
- **25 measures** in display folders: Sales, Time Intelligence, Targets, Ops

| Measure | Idea |
|---|---|
| `Revenue` | `KEEPFILTERS(order_status IN {"Completed","Shipped"})`. The business rule lives in one place |
| `Revenue PY`, `YoY %`, `YTD`, `MTD` | Time intelligence. Needs `dim_date` marked as the date table (`dataCategory: Time`) |
| `Target`, `Target Attainment %` | Monthly targets joined on `month_start_date` (first of month) |
| `Attainment Color` | Returns a hex colour for conditional formatting |
| `Rep Revenue Rank` | `RANKX(ALLSELECTED(...))` |

## Tips & tricks
- **Use explicit measures, never implicit sums.** Hide raw numeric columns so report authors *must* use measures.
- **Hide keys and audit columns.** Use sort-by columns (`month_name` → `month_number`).
- **Write descriptions** on measures. They show as tooltips and help Copilot / Q&A.
- **Handle facts at different grains** (daily sales vs monthly targets) by relating both to `dim_date`. Targets sit on the 1st of the month, so slice them by month or higher.
- **Turn on Direct Lake auto-update** ("keep data up to date") so new Delta versions show up without a refresh. Or refresh from the pipeline.

## Gotchas
- Direct Lake on the SQL endpoint **falls back to DirectQuery** for SQL *views* and when guardrails (row/file counts per capacity SKU) are exceeded. Model over tables.
- No calculated columns or calculated tables on Direct Lake tables. Compute them upstream in the notebook (like `dim_date`).
